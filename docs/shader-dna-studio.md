# Shader DNA Studio

Студия доступна на сайте по `/dna` и в Android через «DNA Studio · создать по идее». На странице работы есть действие «В DNA Studio»; в Android оно находится в панели обсуждения. Можно выбрать до трёх публичных версий, описать идею, получить два независимых варианта, настроить параметры, сохранить приватный черновик или опубликовать работу. Редактор кода остаётся настольным.

## Подключение

Локально скопируйте `.env.example` в `.env`, задайте `OPENROUTER_API_KEY` и выполните `npm run dev`. Ключ читает только Node-сервер. Без него студия показывает состояние «генерация пока не подключена», но позволяет подготовить идею. Реальные модели требуют доступного баланса OpenRouter.

По умолчанию используются две разные модели:

- `~deepseek/deepseek-flash-latest`
- `~openai/gpt-luna-latest`

Поменять их можно серверной переменной `DNA_MODELS`: ровно два разных идентификатора через запятую. Выбор фиксируется при создании генерации. Повтор варианта использует ту же модель. Клиенты не могут задавать модель, URL провайдера, ключ или число токенов.

Для облачного окружения примените миграцию `supabase/migrations/20260927080553_shader_dna_studio.sql`, задайте `OPENROUTER_API_KEY` в секретах Edge Functions и обновите функцию `gallery`. Затем публикуйте веб-сборку и устанавливайте новый APK. Порядок важен: сначала база и API, затем клиенты. В `VITE_*` секретный ключ добавлять нельзя. Порядок обычного выпуска проекта описан в [ci-cd.md](ci-cd.md).

В текущей работе подготовлены исходники и локальные сборки. Миграция и функция не применялись к публичному проекту; реальные платные обращения к OpenRouter не выполнялись.

## Устройство сервера

Локальная PGlite и облачный Postgres используют один модуль `supabase/functions/_shared/dna-core.mjs`. Модуль провайдера `dna-provider.mjs` обращается к OpenRouter. Таблица `dna_jobs` хранит владельца, ключ запроса, описание, пожелания к параметрам и снимки референсов. `dna_variants` содержит две независимые задачи, результат, ошибки, число попыток и ссылку на черновик.

Создание и лимиты сериализованы блокировкой строки пользователя внутри короткой транзакции. Вызовы OpenRouter выполняются после транзакции. Начать можно одну активную генерацию на аккаунт и до десяти за скользящие 24 часа. Для каждого варианта разрешены три попытки, включая исходную; повтор доступен в течение суток после создания. Неудачные и отменённые запуски учитываются в лимите.

`request_id` повторного запроса с тем же содержимым возвращает прежнюю генерацию. Другое содержимое с тем же ключом отклоняется. Клиенты сохраняют ключ до отправки и используют его после потери ответа. Повтор варианта использует `expected_attempts`, поэтому два устройства не должны одновременно оплачивать один и тот же повтор.

Рабочий процесс атомарно переводит вариант из `queued` в `running`, получает случайный `lease_token` на 330 секунд и делает один запрос к модели с тайм-аутом 300 секунд. Для обеих моделей передаётся уровень рассуждения `high`. Ответ ограничен 180 КБ, результат — 30 000 символов кода, 12 параметрами, описанием до 300 символов и 16 000 выходными токенами (включая токены рассуждения). Если модель прислала длинное описание, сервер оставляет первое законченное предложение или обрезает по границе слова. Автоматических повторных обращений к платному провайдеру нет. В облаке реальное время ограничено тарифом Supabase: до 150 секунд на Free и до 400 секунд на платных планах.

Переходы:

```text
queued → running → ready
                 → failed → queued  (явный повтор)
queued / running → cancelled
просроченный running → failed (interrupted)
queued старше 10 минут → failed (interrupted)
```

Результат записывается только при совпадении токена и действующей аренде. Отмена и просрочка отсекают запоздалые ответы. Отмена останавливает принятие результата; уже принятый провайдером запрос может продолжить выполняться и учитываться в его расходах.

На локальном сервере восстановление запускается при старте и каждые 30 секунд. В Supabase две задачи передаются `EdgeRuntime.waitUntil`. При открытии истории или генерации API проверяет просроченные задачи и запускает ещё не взятые из очереди. Если Edge Function оборвалась между записью задачи и запуском, пользовательское обращение восстановит очередь; отдельного облачного планировщика в этой версии нет. После истечения аренды повтор требует явного нажатия пользователя.

## Права, публикация и происхождение

Все действия с генерациями, кроме чтения конфигурации, требуют входа. Чужие генерации, варианты, черновики и страницы истории недоступны. На новых облачных таблицах включён RLS и отозваны права `anon` / `authenticated`; работа с ними идёт только через API с проверкой владельца. Ключ OpenRouter, исходные ответы провайдера и диагностические тела его ошибок не возвращаются клиентам.

Референс принимается только как UUID существующей публичной версии. Сервер самостоятельно читает исходник, параметры, автора и лицензию. Приватные черновики, скрытые работы, заблокированные авторы и подмена исходника клиентом исключены. Снимок фиксируется на момент создания и одинаков для обеих моделей. При явном повторе сервер заново проверяет доступность референсов.

`dna_save` создаёт один обычный приватный черновик на вариант. Повторное сохранение возвращает его идентификатор, сохраняя сделанные вручную правки. После удаления черновика его можно создать снова. Выбранные настройки становятся значениями по умолчанию при первом сохранении.

`dna_publish` использует UUID варианта как ключ публикации: повтор, в том числе одновременный с другого устройства, возвращает уже созданную работу. Первые сохранённые настройки выигрывают. Редактирование опубликованной работы идёт через обычный редактор и создаёт новую версию.

Поле `revisions.dna_origin` содержит модель и происхождение результата, без приватного пользовательского задания. Оно переносится в последующие версии, ручные ремиксы и Android-пакет (`dnaOrigin`). Ссылки указывают на конкретные исходные версии. Черновик для редактора хранит `dnaVariantId`; при публикации сервер проверяет владельца исходного варианта. Для результата используется MIT с сохранением информации о лицензиях и авторах референсов.

## Проверки и границы

Запуск: `npm test`, `npm run build`; в Android — `:app:assembleDebug` и `:app:lintDebug`.

Итоговая проверка 27 сентября 2026: 20 из 20 серверных тестов прошли; веб-сборка, проверка типов Edge Function через Deno, Android debug APK и Android Lint завершились успешно. В Android Lint остались предупреждения без ошибок; Vite предупреждает о крупных чанках. Редактор кода загружается отдельно: основной сжатый JS уменьшился примерно с 329 до 159 КБ. APK находится в `apps/android/app/build/outputs/apk/debug/app-debug.apk`.

Серверные тесты проверяют независимость вариантов, идемпотентность, конкурирующие старты и публикации, права доступа, ограничения, частичные ошибки, отмену, просрочку, восстановление базы после перезапуска, сохранение ручных правок и атрибуции, применимость миграции и закрытый прямой доступ к таблицам. Отдельный HTTP-тест проходит путь до публичного Android-пакета на настоящем локальном сервере с подменённым только транспортом OpenRouter. Доступ к реальным моделям для этих проверок не нужен.

Сервер проверяет структуру ответа и совместимость с ограниченным шейдерным профилем. Компиляция и предпросмотр выполняются на WebGL 2 / GLES 3 устройства; публикация в интерфейсе доступна после успешной локальной компиляции. Статическая проверка не гарантирует одинаковую картинку, скорость или отсутствие ошибок на всех GPU. При проблеме результат можно сохранить в черновик и исправить на компьютере. После потери WebGL-контекста превью пытается восстановиться, а разрешение на публикацию проверяется заново.

Ручная проверка реальных моделей, визуального качества и поведения на физических устройствах остаётся за владельцем проекта.
