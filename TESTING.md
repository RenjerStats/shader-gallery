# Проверка Shader Gallery

## Автоматические проверки

```powershell
npm ci
npm run build
npm test
```

Из `apps/android/` соберите `:app:assembleDebug` с JDK 17 и Android SDK 35. Автотесты проверяют общие данные двух пользователей, права на чужие работы, идемпотентную публикацию, сохранение конфликтующих черновиков, настройки и скрытие публикации модератором. Они не заменяют проверку WebGL/GLES на устройстве.

## Веб: пройти вручную в двух браузерных профилях

1. Открыть главную страницу без входа. Создать аккаунт A, взять шаблон, проверить код и опубликовать работу.
2. В профиле B найти её по названию, подписаться на A, оставить комментарий, поставить лайк и сохранить. Перезагрузить страницу, проверить ленту «Подписки» и «Сохранённое».
3. Из B сделать ремикс. Проверить связь с конкретной версией оригинала и лицензию. Из A выпустить новую версию: ремикс должен по-прежнему ссылаться на старую.
4. В редакторе сломать GLSL: последняя рабочая картинка остаётся, публикация блокируется. Закрыть страницу и восстановить локальный черновик. Сохранить черновик в облако с двух устройств с одной базовой версией: должны сохраниться обе копии.
5. Настроить цвет/число у работы, сохранить пресет, войти снова и проверить его. Открыть permalink в новом профиле. Проверить QR, исходник, комментарии и пустые состояния.
6. Отправить жалобу, открыть модерацию аккаунтом с записью в таблице `moderators`, скрыть работу. Анонимный посетитель больше не должен видеть её и получать пакет.

## Android: два физических устройства по очереди

1. Подключить первый телефон, установить debug APK, выполнить `adb -s SERIAL reverse tcp:4173 tcp:4173`. В каталоге проверить «Новое», «Подборка», поиск по названию/тегу, категории и «Показать ещё». Открыть карточку, затем прямую ссылку `/works/WORK_ID?revision=REVISION_ID`. Отключить первый телефон и повторить на втором: одновременное подключение не требуется.
2. Войти в тот же аккаунт, что и на сайте. Проверить подписку, «Подписки», лайк, сохранение, «Сохранённое», комментарий, выход и повторный вход. Гость должен получить форму входа перед действием. На телефоне не должно быть редактора кода.
3. Проверить предпросмотр, изменения цвета/числа, касания и работу `iTilt` при наклоне. Повторить на устройстве без rotation vector или в эмуляторе для нейтрального fallback.
4. Открыть системный экран установки и установить живые обои. Убедиться, что выбранная версия работает на рабочем столе, а не только в приложении.
5. Включить режим полёта, перезапустить процесс приложения и лаунчер, повернуть экран. Работа и настройки должны восстановиться из локального пакета.
6. Изменить качество 50/75/100% и частоту 15/30/60 FPS. Измерить реальное время кадра, температуру и расход энергии относительно статических обоев на обоих GPU. При скрытых обоях проверить прекращение кадров и слушателя датчика.
7. Попробовать тяжёлый и ошибочный шейдер. Ошибка нового пакета не должна заменить ранее установленную рабочую версию без успешного предпросмотра. Повторить после потери EGL surface.

Записать модель, Android API, GPU, лаунчер, результат и известные отклонения. До этого Android-сценарий нельзя считать принятым.
